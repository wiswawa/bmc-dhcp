# 在 Mac 上连接新的 BMC

## 准备

- macOS 15 或更高版本（当前随包 Python 运行时要求）；使用与 Mac 架构匹配的应用包。
- USB-C/Thunderbolt 以太网卡，一根网线。
- BMC 已通电并启用 DHCP；连接服务器的专用管理口。

## 使用

1. 解压并打开 **BMC DHCP.app**。应用可放入「应用程序」目录，运行时无需另装 Python 或浏览器组件。
2. 按 macOS 系统提示输入管理员密码。打开界面还不会启动 DHCP。
3. 在「连接设置」里选择接 BMC 的以太网口。不要选择上网用的网口，使用直连或隔离管理交换机。
4. 保持默认 `10.99.0.0/24`、地址池 `.100–.200`、租期 300 秒，点击「启动服务」。如已有网段冲突，先修改这些值。
5. 等待右侧「租约」显示 BMC 地址。点击「打开管理页」在默认浏览器连接，也可以复制 IP 用于 SSH/IPMI 客户端。
6. 用完点击「停止服务」，或关闭窗口 / 按 ⌘Q。工具停止 DHCP 并尝试恢复所选网口原配置；恢复失败会记录日志，并保留备份供下次恢复。

## 租约一直为空

- 确认网线接的是 BMC 管理口，网口有链路，BMC 已通电。
- 服务启动后等待 BMC 重新发起 DHCP；可在服务器 BIOS / BMC 设置中切换为 DHCP。
- 若 BMC 使用静态 IP，切到「IP 探测」，先侦听或扫描已知管理网段。DHCP 服务不能强制更改静态 BMC 地址。
- 点击「运行诊断」，查看管理员权限、BPF 和 UDP/67 占用。系统的「互联网共享」可能占用 DHCP 端口。
- macOS 询问本地网络访问时选择允许。

## 日志与恢复

应用菜单「帮助 → 打开运行日志」，文件位于 `~/Library/Logs/BMC DHCP.log`。
租约与恢复记录位于 `~/.bmcd/`。强制结束进程后，重新打开 App 会检查并尝试恢复上次留下的网口配置。

## 发布状态

当前应用使用本地 ad-hoc 签名，没有 Apple Developer ID 签名及公证。跨机器传输后的首次打开可能需要在「系统设置 → 隐私与安全性」允许运行。本机构建的架构见压缩包文件名；真实 BMC 联调结果见源码中的 `docs/VALIDATION.md`。
